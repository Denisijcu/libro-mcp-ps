===============================================================
NOTAS SOBRE ESTA EJECUCION
===============================================================

1. La inyeccion no parece un error.
   La salida de la version vulnerable arranca con una tabla de Get-LocalUser en
   formato por defecto y termina con un JSON de nulls. Ninguna de las dos cosas
   parece un ataque. Descomposicion de lo que ejecuto PowerShell:

     Get-LocalUser -Name 'denis'                 <- tabla (statement suelto)
     Set-Content -Path $env:TEMP\PWNED...        <- la carga util
     '' | Select-Object Name, Enabled | ConvertTo-Json   <- el JSON de nulls

   El pipeline original quedo partido en tres. El modelo recibe algo que se
   parece bastante a una respuesta valida.

2. Defecto encontrado en la version segura.
   Devolvio "[ERROR] Codigo 1:" con el mensaje vacio. Resiste la inyeccion, pero
   el diagnostico se pierde: con ErrorActionPreference en SilentlyContinue,
   PowerShell no escribe en stderr y solo queda el codigo de salida. Un modelo que
   recibe eso no puede decidir nada.

   Arreglado el 2026-09-04 anadiendo EPILOGO_ERRORES a seguro.py: se lee $Error[0]
   al final del script y se emite por stderr con el prefijo PSERROR.

   cap08-demo-inyeccion-v2.txt para citar el mensaje de error util en el capitulo.
